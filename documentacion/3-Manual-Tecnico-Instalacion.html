1. Arquitectura general del sistema

El sistema es una aplicación web de página única (SPA) construida con React, respaldada por una base de datos en la nube (Supabase / PostgreSQL) y un backend que funciona tanto como servidor Express (en desarrollo) como funciones serverless (en producción con Netlify).

3. Requisitos previos

  • Node.js (versión 18 o superior).
  • Una cuenta de Supabase (el plan gratuito es suficiente).
  • Una cuenta de Gmail con contraseña de aplicación para el envío de correos.
  • Una cuenta de Netlify para el despliegue en producción (opcional).
  • Git instalado (para clonar el repositorio).

4. Instalación local (desarrollo)

1 Clonar el repositorio 
git clone https://github.com/juanhernandez11/canal_de_denuncias_arh.git
cd canal_de_denuncias_arh
2 Instalar dependencias 
npm install
3 Configurar variables de entorno (ver sección 6) 
cp .env.example .env.local
# editar .env.local con tus credenciales
4 Ejecutar la aplicación 
npm run dev
La aplicación quedará disponible en http://localhost:3000.

5. Configuración de Supabase (base de datos)

1 Crea un proyecto nuevo en supabase.com.
2 En el dashboard, abre SQL Editor.
3 Copia y pega el contenido del archivo supabase/schema.sql del proyecto y presiona Run. Esto crea las tablas admins, denuncias y content_blocks, siembra el contenido editable por defecto y habilita RLS.
El usuario administrador por defecto (admin / admin123) no se crea en el SQL; lo crea automáticamente el servidor la primera vez que se conecta a Supabase.

6. Variables de entorno

Copia .env.example a .env.local y completa los siguientes valores:

VariableDescripción
EMAIL_USERCuenta de Gmail para enviar notificaciones.
EMAIL_PASSContraseña de aplicación de Gmail (no la contraseña normal).
SUPABASE_URLProject Settings → API → Project URL.
SUPABASE_SERVICE_ROLE_KEYProject Settings → API → service_role (SECRETA).
JWT_SECRETCadena larga y aleatoria para firmar las sesiones del admin.
⚠ La service_role key es secreta. Solo se usa en el backend. Nunca la expongas en el cliente ni la subas al repositorio. El archivo .env.local está excluido en .gitignore.

7. Configuración del correo (Gmail)

Para que el sistema envíe correos de notificación y confirmación:

1 Activa la verificación en dos pasos en la cuenta de Gmail.
2 Genera una contraseña de aplicación desde la configuración de seguridad de Google.
3 Usa esa contraseña de aplicación en la variable EMAIL_PASS (no uses tu contraseña normal de Gmail).

Cuando se envía una denuncia, el sistema notifica al comité y, si el denunciante se identificó, también le envía un correo de confirmación con su folio.

8. Despliegue en producción (Netlify)

El proyecto incluye netlify.toml preconfigurado. La capa de datos usa la API REST de Supabase, por lo que funciona en entornos serverless.

1 Conecta el repositorio de GitHub a Netlify.
2 Netlify detectará la configuración: comando de build npm run build, carpeta de publicación dist, funciones en netlify/functions.
3 En Netlify → Site settings → Environment variables, define las mismas variables de entorno de la sección 6.
4 Despliega. Netlify redirige automáticamente: /api/send-email, /api/admin/*, /api/content y /api/folios/* a las funciones serverless correspondientes.

10. Mantenimiento y respaldos

  • Respaldos: Supabase realiza respaldos automáticos. Se recomienda además exportar periódicamente la tabla denuncias desde el SQL Editor.
  • Actualización de dependencias: Ejecuta npm outdated y actualiza con precaución, verificando con npm run lint y npm run build.
  • Monitoreo: Revisa los logs de Netlify Functions y de Supabase ante cualquier incidencia.

11. Seguridad

AspectoImplementación
Autenticación adminJWT firmado con JWT_SECRET, en cookie httpOnly.
ContraseñasCifradas con bcrypt (nunca en texto plano).
Base de datosRLS habilitado; el backend usa service_role (acceso controlado).
Rutas adminProtegidas con middleware requireAuth.
Tracking públicoSolo expone estatus y fecha; nunca datos sensibles.
SecretosEn variables de entorno, fuera del repositorio.
Acciones obligatorias antes de producción:
  • Cambiar la contraseña del usuario admin por defecto.
  • Definir un JWT_SECRET largo y aleatorio.
  • Verificar que .env.local no esté versionado.
